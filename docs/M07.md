# M07 — Videoconsulta con LiveKit

## Estado

Implementación propuesta/aprobada y compilada localmente; la migración 011 fue
aplicada y el esquema quedó inspeccionado. La validación funcional con dos
participantes y credenciales LiveKit aún está pendiente. No habilita atención
clínica real ni pacientes reales.

## Decisiones

- Proveedor inicial: LiveKit Cloud.
- Flutter usa livekit_client; el portal usa livekit-client.
- La API emite JWT efímeros con permisos de sala; el token crudo no se persiste.
- La sala se identifica por una referencia derivada de la cita y solo se entrega
  después de validar autorización, cita confirmada, check-in H06 Ready y ventana.
- El paciente crea/entra en estado Waiting; el profesional asignado admite y
  pasa la sesión a Active.
- Cancelar o reprogramar una cita termina cualquier sesión abierta asociada.
- No se implementan grabación, transcripción, documentos, diagnóstico ni encuentro
  clínico M08.

## Implementación

Backend:

- Features/Video/VideoController.cs: token, estado, admisión, fin y eventos técnicos.
- Infrastructure/Video/LiveKitTokenService.cs: JWT HS256 compatible con LiveKit.
- Infrastructure/Persistence/Migrations/011_video_sessions.sql: sesiones y eventos.
- AccessCatalog: permiso video.practitioner.

Flutter:

- features/video_visit/presentation/video_visit_screen.dart: conexión real,
  publicación de cámara/micrófono, render de participantes, mute, cámara y salida.
- El botón aparece únicamente cuando el check-in H06 está en Ready.
- Se declararon permisos Android/iOS de cámara y micrófono.

Portal:

- /videoconsulta: el profesional consulta una cita, admite al paciente y entra
  a la misma sala LiveKit.
- La ruta exige video.practitioner; no se expone a Admission ni Support.

## Configuración privada

En api/src/.env, nunca en Git:

    LiveKit__Url=wss://<proyecto>.livekit.cloud
    LiveKit__ApiKey=<clave>
    LiveKit__ApiSecret=<secreto>
    LiveKit__TokenTtlSeconds=300
